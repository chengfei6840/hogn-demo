1. 系统定位与边界

1.1 一句话定位

面向电网金具串询价场景的报价协作工作台：把客户的一份物料清单 Excel，拆成 N 个报价包，由销售、技术、财务、审批人按固定门禁接力，最终输出可签发的对外报价单。

1.2 解决的三个核心问题

问题现状痛点系统做法
清单拆包靠人一份 32 包的物料清单，人工按包号拆分、统计电压/数量/交货地，易错自动识别工作表与表头，按「包名称 + 包号」聚合成报价包，同时汇总技术编码种类数、电压等级、各地交货数量
串型选型无依据销售凭经验报串型号，技术返工三级检索（技术规范编码 → 串型号 → 图册版本/图号），命中后带出 BOM 子件与 U9 成本，差异项逐条提示
报价边界不清谁改了价格、依据是什么，事后无法追溯每次技术改动/核价/审批/签发均写审计条目 + 版本号；签发时冻结快照，报价单可回溯到子件级

不做的事代码事实

4.3 「并行协作」的真实含义

名字叫并行，代码是串行门禁：

1. 销售先完成 confirmSales（把 salesConfirmed 打成当前版本号）。

2. 技术才能确认：confirmTech 首先校验 salesConfirmed === version，否则报「请先等待销售完成需求确认」。

3. 技术侧可选「总监自己完成」或「指派技术员工」：

- 员工模式下，员工改完必须点「提交技术结果」，状态 assigned → submitted；

- 总监可「退回并通知技术人员」，状态回 assigned，退回原因留痕；

- 最终 confirmTech 只有技术总监能点。

4. 双确认齐了，canFinance() 才为真。

注意：技术员工只能看到指派给自己的包（technicalWorkflowScope 过滤），台账会出现「当前工作表下暂无可见报价包」。这是设计，不是 bug，但演示前必须切到对应人员。

4.4 财务核价

步骤动作系统行为
1打开核价页展示子件成本明细（U9 价 / 参考子件成本 / 本次核算价三列）
2修改子件核算价实时重算「串单位成本 = Σ(子件单价 × 每套用量)」，缺项单独计数
3设定单项毛利率未税单价 = 成本 ÷ (1 − 毛利率)；含税 = 未税 × (1 + 税率)
4选报价方案保守 25% / 标准 20% / 竞争 15% / 自定义 10%，可逐项覆盖
5查看风险提醒含税总额 ≥ 金额阈值、毛利率 < 红线、手工标记特殊商务事项，三类提示只提醒、不加审批节点
6保存核价写草稿；税率、计价口径、风险标记一并落库
7提交审批先跑完整性校验（见 7.4），通过后按流程快照生成审批链

4.5 审批签发

  • 审批链来自「审批与流程配置」中已启用的流程版本，按连线顺序执行，不看画布位置。
  • 流程被复制成快照存进报价包，之后改模板不影响已创建的包。
  • 节点动作只有两种：approve（审批）/ issue（签发）。最后一个节点必须是唯一的签发节点。
  • 只能由「当前节点指定人」操作，不能跳节点；run.basis 与当前核价依据比对，核价一改，审批立即失效，需重新提交。
  • 签发动作会冻结快照：货物项、子件对外报价、审批记录、审计日志全部写入 snapshots[0]，此后报价单只能基于快照生成。

4.6 外发与成交

动作前置结果
调整报价阶段 ∈ {已出具, 客户议价中} 且未归档；只能改最新快照串价与子件价同步改写，重算含税总额，写审计
登记外发阶段 = 已出具stage → 客户议价中，记录外发时间
登记成交阶段 = 客户议价中，必须填结果 + 依据stage → 已成交/未成交/已取消，写 archivedAt，从在办列表移入历史库
取消归档阶段 ∈ 三个终态回到「客户议价中」，原成交记录保留在日志

5. 关键子流程

5.1 项目创建与物料清单解析

输入要求：.xlsx（明确拒绝 .xls）；必须选择销售/技术/财务三位负责人；技术负责人必须是技术总监。

解析规则（material-list.ts）：

规则实现
表头识别每个工作表扫描前 40 行，找到同时含「数量」和「单位」列的行作为表头
列名兼容每类字段支持 2–3 个别名，如包名称 = 包名称/报价包名称/标包名称；电压 = 工程电压等级/电压等级
无效行过滤以「合计/总计/小计/说明/备注」开头的行跳过；空行跳过；重复表头行跳过
拆包键包名称 + 包号；包名称缺失时用工作表名兜底
包级汇总货物项数、技术规范编码种类数（去重）、电压等级集合、按单位汇总数量
交货地汇总按「省份 + 工程名称 + 交货地点」三元组聚合；省份用 34 个省级别名匹配，匹配不到记「地域待确认」
工作表归属每个包记住 sourceWorksheetId，后续按类别筛选、统计都依赖它

创建时的硬校验（任一不满足则「创建项目」按钮禁用或报错）：

1. 项目名称非空；

2. 物料清单文件后缀为 .xlsx；

3. 三个负责人均为已启用且角色匹配的用户，技术负责人 ∈ {李总监}；

4. 至少选择一个工作表，且已完成解析（已解析的工作表集合 === 当前勾选集合，这是最容易卡住外部演示的一条）；

5. 每个报价包的 sourceWorksheetId 必须落在所选工作表集合内；

6. 至少识别出 1 个报价包。

解析后必须点「解析所选工作表」，「创建项目」才会解锁。只点「载入演示文档」不解析，按钮会一直灰着且无提示。

5.2 串型检索与选型

四条检索路由，自动模式按顺序尝试：

路由匹配键说明
0技术规范编码 spec最精确，优先
1串型号 model支持护/铝后缀容差：无后缀时可匹配两种包缠物配置
2图册版本 + 图号图册版本必须一致，图号命中主图号或备用图号均可
3兜底前三路全空时按货物名称前 8 字模糊匹配

命中后按「差异项数量」升序排序，差异维度：电压等级、适用导线、串型号、图册版本、图号。差异只做展示，不阻断采用。

采用候选时实际生效的校验（select 动作）：

校验说明
候选必须存在于图册库否则报「候选不存在」
独立物资不能选串型否则报「独立物资不能选择串型」
必须填写匹配条件与选定依据否则报「请填写匹配条件及选定依据」
阶段必须可编辑已进下游则要求退回或建新版本
技术员工只能改被指派的包否则报「当前包技术任务未指派给你」
实证提醒：candidateAdoptionIssues()（强制技术角色采用、阶段限制、导线补齐、差异逐条拦截）已在 model.ts 中定义并在 store.ts 里 import，但全仓无任何调用点——这组规则目前是死代码，不生效。选型差异只影响排序与展示。

5.3 技术指派

技术总监 → 选择包（可多选）→ 指定技术员工 → 员工处理 → 提交 → 总监确认 / 退回
状态含义谁可操作
assigned已指派待处理被指派员工
submitted员工已提交，等总监确认技术总监
退回状态回 assigned + 退回原因技术总监

指派前校验：操作人必须是技术总监；包的销售确认必须已完成（salesConfirmed === version）；包未归档且处于并行协作阶段。

指派后员工只能看到被指派的包，且提交时会校验「变更摘要」，把本人改动按货物项汇总给总监。

5.4 版本失效与重走

任何技术依据变化都会调用 invalidate()：

触发动作后果
重新解析资料重建货物项、清空双确认
修改串型参数 / 编辑子件 / 改报价范围version + 1；salesConfirmed、techConfirmed 置空；U9 成本与带出结果清空；审批 run 若在跑则置 returned
财务侧改价后提交新审批旧审批进 approvalHistory，新建 run
已签发后「创建新版本」历史 U9 价转存 historicalU9Data，新版本沿用归档价，技术确认后再刷新维护库价
关键设计：版本号是门禁的主键。所有「已确认」都存成 xxx === version，版本一变自动失效，不依赖人工清理状态。

5.5 批量处理

能力前提行为
批量进入同项目、均未归档、下一步动作完全一致（capability key 相同）任一包无权或环节不同即拒绝，并说明原因
批量解析销售 + 解析权限 + 全部包均为本人负责 + 阶段 ∈ {资料整理, 并行协作}首包保留待确认项，其余包预填完整
批量确认销售/技术同一环节逐包执行，结果逐包回显（成功/失败原因）
批量指派技术技术总监 + 包均已销售确认可全选，逐个写 technicalExecution
聚合视图已批量进入BOM/核价/报价按包分节渲染，各包税率、成本、审批、版本独立，互不影响

6. 状态机

6.1 状态定义

状态类型可写动作出口
资料整理在办登记资料、启动解析、编辑包信息→ 并行协作
并行协作在办销售确认、技术编辑/选型、指派、技术确认、驳回→ 财务核价（双确认后）；回退到自己（版本+1）
财务核价在办改子件成本、改价、保存核价、提交审批、驳回→ 审批签发 / 可出具报价
审批签发在办当前节点通过、退回→ 下一节点 / 可出具报价 / 财务核价
可出具报价在办签发节点执行签发→ 已出具
已出具在办调整对外报价、登记外发、创建新版本→ 客户议价中 / 并行协作（新版本）
客户议价中在办调整报价、登记成交、创建新版本→ 已成交 / 未成交 / 已取消
已成交 / 未成交 / 已取消终态仅「取消归档」→ 客户议价中

6.2 允许的状态迁移（含守卫条件）

From → To触发守卫
资料整理 → 并行协作启动解析有资料；包可编辑
并行协作 → 财务核价技术总监确认销售已确认 + 技术信息完整 + 无技术阻断
并行协作 → 并行协作任一技术改动版本 +1，双确认清空
财务核价 → 并行协作技术驳回 / 退回到技术必须填原因
财务核价 → 审批签发/可出具报价提交审批核价完整性校验通过；存在已启用流程
审批签发 → 审批签发节点通过当前节点指定人；basis 未变
审批签发 → 财务核价审批退回当前节点人；填原因；run 重置为 pending
可出具报价 → 已出具签发当前节点 action=issue 且本人
已出具 → 客户议价中登记外发外发负责人
客户议价中 → 终态登记成交必须选结果 + 填依据
终态 → 客户议价中取消归档成交记录保留
遗留态「董事长审批」在读取时被 normalizePackage() 自动迁移：若当前节点是签发 → 可出具报价，否则 → 财务核价。董事长角色只读。

8. 数据模型

Project（项目）
 ├─ 基本信息：名称、客户、地区、电网类型、寒区标准
 ├─ 物料清单文件 + 工作表集合（materialWorksheets）
 └─ Package[]（报价包）
      ├─ 标识：packageNo、packageName、voltageLevel、materialWorksheetId
      ├─ 状态：stage、version、archivedAt、financeReachedAt
      ├─ 双确认：salesConfirmed、techConfirmed（存版本号）
      ├─ 流程：processParticipants（7 类负责人）、approvalFlowSnapshot、approvalRun / approvalHistory
      ├─ 技术：technicalExecution（director / employee + assigned / submitted）、rejection
      ├─ 明细：Item[]
      │    └─ Part[]（子件：型号、用量、材质、U9 料号、图号、工艺路线、候选选型、参考子件、技术变更）
      ├─ 价格：tax、pricingNote、pricingSchemes、selectedSchemeId、u9Data / historicalU9Data
      ├─ 快照：Snapshot[]（version、items、quoteParts、approval、audit、total、cost）
      └─ 审计：Audit[]（时间、角色、动作、明细、版本、变更前后快照）

三个要点：

1. 包是报价的最小单位，不是项目。同一项目下不同包可以停在完全不同的阶段。

2. 快照只增不改。签发后调价改的是快照里的对外价，历史快照保留。

3. 审计带 before/after。技术改动、核价改动都记录 changes[]，可按角色汇总（PackageOperationSummaryDialog）。
