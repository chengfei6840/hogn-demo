# PRD V1.2：报价签发职责修订

本修订与已封存 V1.1 合并使用，仅覆盖下列职责、权限和场景。V1.1 及其交接封存文件保持不变。本修订已获本任务用户“按你这一版来改”授权，未重新运行完整 pm-start 审查。

## 依据与决定

老板整理的《红光金具智能报价系统_解决方案说明_2026-09-03.md》第161行：“系统建议 + 规则引擎出价，财务加系数后人工签发，技术环节可屏蔽最终价”。合同规定报价单生成及权限审批，但未指定最终签发角色。

确定分工：财务核价 → 条件触发时老板审批 → 财务签发 → 销售下载并对外提供。

## 覆盖规则

1. 财务是正式报价签发操作的执行角色。销售、技术、老板和管理员不能代替财务签发。
2. 需双确认、财务审核及必要老板审批完成，并满足 V1.1 版本一致性和金额校验后才可签发。老板审批通过后进入“待财务签发”。
3. 签发成功冻结报价快照，并记录签发人、时间、需求版本、价格和审批依据。销售下载已签发版本，不得直接更改已签发价格。
4. 销售对外提供报价是业务职责。本原型只下载文件，不自动发送客户，也不把下载记录当作客户已收到。
5. 销售可以发起新版本，财务重核，按条件重新审批和签发。旧报价保持不变。
6. V1.1 的角色权限、待出具状态执行人、报价出具场景 SC-26、版本场景 SC-27、输出场景 SC-28、权限场景 SC-29 及其派生交接描述中的签发主体，统一按本修订执行。
7. 老板单项调价尚未确认，不在本次实施范围。现有权限仍为审批、退回及原有演示审批配置。

## 验收

- 审批完成后，财务可签发；销售不能触发签发命令。
- 审批未完成时，即使财务也不能签发。
- 财务签发后生成含签发人和时间的冻结快照，销售可下载。
- 老板通过不自动签发；销售下载不改变审批和签发状态。
- 历史原型快照保留，不补写虚假的财务签发人。

原型仍使用浏览器本地状态和CSV演示；正式服务端授权与签发事务要求沿用V1.1。
