原型用于检查权限、页面操作和数据流转。真实解析、ZIP 处理、U9 接口、生产身份认证、正式报表和三维出图需要后续开发，不能以原型演示结果代替合同验收。

## 2 产品目标与分期

### 2.1 产品目标

1. 保留客户原始需求和来源，减少货物项遗漏、编码混用与人工转录。
2. 按客户确认路径检索金具串，展示候选、技术依据、差异及缺失项。
3. 将销售补资料与技术核对纳入同一任务，明确当前负责人和下一步。
4. 基于已确认技术结果形成可复核价格，按权限审批并保存报价快照。
5. 按合同逐步扩展成本库、项目报价比对、报告关联和标准件出图。

本轮原型验收看业务操作是否闭合。合同效率、准确率、覆盖率和并发指标需在真实服务、真实样本及明确计算口径下验收。

## 4 业务对象与数据关系

资料批次属于文件接入层，不等于业务询价包。一个批次可以包含多个文件及ZIP，一个文件可能包含多个包，同一包也可能引用多个技术文件。

```text
资料批次 → 文件 / ZIP内部文件 → 来源位置
                           ↓
工程或询价包 → 客户货物项 → 金具串型 → 串内子件
                           ↓              ↓
                      检索候选         物料/价格依据
                           ↓              ↓
                    销售与技术确认 → 核价 → 审批 → 报价快照
```

| 对象 | 关键属性 | 约束 |
| --- | --- | --- |
| 询价包 | 客户、项目、分标、包名称、分包编号、负责人、当前阶段 | 包名称与分包编号分别保存 |
| 资料批次 | 批次号、上传人、时间、文件清单、异常 | 一次提交形成批次，不覆盖旧批次 |
| 文件 | 原始名称、哈希、类型、ZIP内部路径、版本、状态 | 原件与转换结果分别留存 |
| 客户货物项 | 原始序号、名称、描述、数量、单位、编码、范围 | 保留客户顺序及原始值 |
| 技术条件 | 电压、导地线、用途、机械与连接条件、图册 | 原值、规范值、确认值及证据分别保存 |
| 候选 | 路径、主库记录ID、命中条件、差异、缺失、来源 | 编码和串号均不能作为唯一成套记录标识 |
| 子件 | 名称、型号、每套用量、单位、材质、单重、U9、图号 | 每套用量与采购数量分别保存 |
| 风险任务 | 规则编号、对象、字段、负责人、状态、阻断阶段、依据 | 一个问题一个当前负责人 |
| 确认记录 | 角色、对象、需求/技术版本、意见、时间 | 确认不得无版本关联 |
| 核价版本 | 物料关联、单价、成本、税费、价格来源、规则版本 | 同口径计算，保存复算输入 |
| 审批记录 | 提交版本、触发原因、审批人、通过/退回、意见 | 退回保留原审批记录 |
| 报价快照 | 原货物项关联、技术/价格版本、金额、模板、审批链 | 已出具版本不可原地改写 |

## 5 并行协作与状态流转

### 5.1 正常流程

1. 销售创建询价，上传原始文件；系统登记文件与异常。
2. 系统输出货物项草稿和来源；销售完成包归属、名称、数量等基本核对。
3. 进入并行协作，销售处理客户资料，技术处理串型及子件问题。
4. 风险卡片可指派到具体人员；指派行为保留问题、版本与阻断。
5. 销售确认客户需求和报价范围；技术逐项确认候选及子件，再确认本包技术结果。
6. 当前版本双确认且核价前阻断解除后，提交财务。
7. 财务核价并复核。达到金额阈值、低于毛利红线或存在主动提交的特殊商务事项时，进入老板审批；其余可进入可出具状态。
8. 老板通过后，销售出具报价并冻结快照。后续变化创建新版本。

### 5.2 阶段门禁

| 当前阶段 | 允许工作 | 进入下一阶段的条件 |
| --- | --- | --- |
| 资料整理 | 上传、文件清点、解析和归属核对 | 有可用货物项草稿和基本归属；技术阻断不要求全部解决 |
| 并行协作 | 补资料、指派、检索、技术确认、范围确认 | 销售确认当前版本；技术确认对应结果；纳入项均满足核价条件 |
| 财务核价 | 保存核价、复核、退回、决定审批路线 | 有效单价、成本、价格依据和商务口径；满足财务校验 |
| 老板审批 | 查看利润及依据、通过或退回 | 老板明确意见，且提交版本未变化 |
| 可出具报价 | 销售生成报价 | 审批仍有效，报价范围完整，生成不可变快照 |
| 已出具 | 查看历史、导出、创建新版本 | 当前版本保持只读；修改创建新版本 |

默认按包汇合。包内某项未完成时其他项继续工作，但不能把整包显示为已完成。调整本次报价范围必须填写原因和依据，在报价中列明排除项；不能借排除项隐藏客户未处理需求。

### 5.3 风险状态

待处理 → 已指派/处理中 → 提交确认 → 已解决。处理中可暂缓或转交；暂缓仍属于未解决状态。确认人驳回处理结果时回到处理中，保留处理记录。

原型将提交确认与有权限角色保存结果合并为一次操作，展示待处理、处理中、暂缓、已解决。正式系统需要独立确认时可保留提交确认状态，依据实际分工配置，不能默认由无权限人员结案。

## 6 退回及版本规则

### 6.1 技术退回

| 触发场景 | 处理要求 | 责任流向 |
| --- | --- | --- |
| 关键导地线、电压或用途缺失 | 明确需要客户补充的字段，保留候选 | 技术转销售 |
| 清单、技术规范与附图冲突 | 列出各来源值，取得明确答复 | 销售取得答复，技术复核 |
| 多候选无法裁定 | 展示差异和可区分条件 | 技术判断，必要时销售补资料 |
| 图册版本/图号不明确 | 补引用或确认版本，不自动合并 | 技术处理或销售补图 |
| 结构、接口、螺栓、均压环等不符 | 明确项目差异，取得设计答复 | 技术复核；需设计时转人工 |
| 子件型号、用量、必要材质不完整 | 补拆解依据及确认结果 | 技术处理 |
| 独立物资或非标分类错误 | 修正范围，保留客户原项 | 技术提出，销售确认范围 |

技术可以用现有资料自行解决的事项直接处理，不要求全部退回销售。需要客户变更要求时，由销售取得并登记客户确认。

### 6.2 财务与老板退回

财务发现数量、物料关系不明确时退回协作；发现商务条款缺失时交销售补充。老板主要因利润、报价策略或风险不满足要求退回财务，填写具体意见。财务调整价格，销售负责必要的客户协商。更换串型或子件必须重新经过技术，不能以利润审批替代技术判断。

### 6.3 修改影响

| 修改 | 正式系统复审要求 | 原型行为 |
| --- | --- | --- |
| 导地线、串型、结构、子件 | 受影响项技术复核，相关核价和审批失效 | 整包双确认失效，重新核对纳入项 |
| 采购数量、报价范围 | 销售重确认，技术检查数量关系，财务重算并判断金额门槛 | 整包双确认失效 |
| 单价、折扣、商务费用 | 财务复核，必要时老板重审 | 退回财务后修改，再审核 |
| 联系人等非技术非价格资料 | 留痕；不重启无关审核 | 本轮未开放该类编辑 |
| 已出具报价 | 新版本重新走适用流程，旧快照只读 | 可创建新需求版本及新报价快照 |

正式系统采用乐观锁或等效版本校验。用户提交的是旧版本时拒绝覆盖，并展示发生变化的字段。所有确认与规则计算须与所消费版本绑定。

正式接入需检查路径越界、异常压缩比、嵌套限制、损坏和加密文件；限制值由部署评估确定。文件内容识别优先于扩展名，不静默丢弃异常。中文ZIP名恢复需保留原始值。OCR只处理需要识别的页面或文件，低质量字段保留原文和问题。

当前解析源码以单个文件参数进入/v1/markdown、/v1/extract、/v1/parse及流式入口。转换和提取职责可复用；ZIP清点、多文件混合归属、跨文件冲突合并需要新增集成能力。底层存在ZIP格式声明不等于业务ZIP链路完成。以实际接口返回为准，不能将旧DocumentIR规划当作当前所有Markdown接口的必有输出。

原型只登记文件名和演示处理进度，不读取上传文件内容，不调用真实模型；初始化提供已解析的示例询价，新建询价应先登记文件并主动启动演示解析。

## 8 国网金具串检索需求

### 8.1 主库与输入

主库以“金具最新分解”的版本快照为主要快速检索源，图册提供技术依据。导入时区分成套记录和子件，保留源表行号、空值及两列同名分册图号。源Excel不由报价流程写回。历史BOM仅在项目与技术条件一致时作为确认参考，其他情况保留为候选依据。

图册已经提供，可打开。完整图册的全文检索、图号索引及页面定位需要后续处理；原型只展示拆解表中的图册引用和行号。

### 8.2 四条路径

| 编号 | 入口与处理 | 必要核对 | 结果 |

### 8.3 结果与字段

| 状态 | 定义 | 可执行操作 |
| --- | --- | --- |
| 准确匹配 | 适用关键条件一致且唯一记录 | 查看依据，技术确认 |
| 存在多条记录 | 两条及以上相关候选 | 对比、补条件或技术裁定 |
| 待确认 | 缺条件、版本差异、冲突或U9不完整 | 指派、补充、核对，保留已知内容 |

核心条件包括技术规范编码、串型号、串型类别或挂线用途、电压、导线或地线、图册名称/版本/图号。补充条件包括分裂数、间距、机械强度、联数、挂点、线夹、引流、绝缘子连接、耐寒耐磨防污倒装、接口和设计答复。最终必需项按串型及检索路径定义。

### 8.4 子件与BOM

FR-BM-01：技术复核子件名称、型号、每套用量、单位、必要材质、单重、U9料号和公司图号，保存来源，生成BOM草稿；通过后供核价引用（AC-09）。

顶层BOM采用哈密北样例中的客户/需求单位、项目/工程、货物名称、数量/单位、技术问题、串料号/品名/规格/描述。子件层采用名称、型号、数量及U9信息。串主数据和子件料号不能混用；缺失保持为空。正式BOM导出格式需按模板复核，原型先展示子件表。

## 10 核价审批与报价输出

### 10.1 核价

FR-PR-01：核价仅消费已确认技术结果。每项价格关联物料、价格版本、规则版本和来源；规则计算可以复现。阶段一以标准件基准价和约定系数为主，单品成本库属于阶段二（AC-14）。

原型采用串级未税单价和单位成本手工录入，提供明确标记的演示价格。未税收入=各项未税单价×采购数量之和；未税成本=各项同口径单位成本×数量之和；毛利率=(收入-成本)/收入。收入为零时不能进入正式审核。

金额精度及每行/整单舍入规则需由财务确认。正式系统使用十进制定点计算，按税费口径保存原始金额和舍入结果；不能使用浮点近似代替财务规则。原型展示人民币、可修改税率和商务说明，所有预填税率与价格仅供演示。

### 10.2 审批

FR-AP-01：按整份报价含税总额与金额阈值比较，达到阈值即提交老板；低于毛利红线或财务主动提交也进入老板审批。触发原因随提交快照保存（AC-15）。

FR-AP-02：老板可查看利润和依据，填写意见后通过或退回财务。老板的利润例外不能解除技术不一致或缺失；报价变化后重判审批（AC-16）。

金额阈值和毛利红线均未获具体数值时，原型默认走老板审批。正式制度确认后配置版本，由老板确认，管理员可按授权维护，但不得自行批准利润例外。

### 10.3 报价

FR-QT-01：只有有效审核通过的版本可生成正式报价；默认使用红光报价模板，客户指定格式时按授权模板输出。报价行可拆分为串、绝缘子和附件，仍需汇总回原客户项（AC-17）。

FR-QT-02：出具时冻结需求、技术、物料、价格、规则、模板及审批版本。变更创建新版本，历史可追溯且不能覆盖（AC-18）。

FR-QT-03：报价列明名称、规格、数量/单位、单价、金额、税费与商务条款，标明不包含的范围；面向客户的文件不包含内部成本和利润（AC-19）。

原型实现固定范围的串级报价、CSV导出及本地快照。正式Excel/PDF模板、一个客户项拆多报价行、文件签章、外发渠道和生产归档存储待集成，不自动发送任何客户消息。

## 11 字典同义词与主数据治理

FR-MD-01：字段字典定义字段代码、名称、对象、类型、单位、别名、适用条件、必填阶段、确认角色、校验和来源格式。各行业规则由项目配置维护，通用解析核心不持有红光审批和报价状态（AC-20）。

### 15.2 合同指标

| 指标 | 合同目标 | 验收方式及条件 |
