## Problem Statement

国网金具报价需要处理清单、规范、图册、BOM 和 U9 物料信息。客户以项目下多个询价包开展广覆盖报价，每个包都可能中标，因此每个包都必须能够独立报价、审批、签发和跟进。现有手工表存在重复录入和更新滞后，图册中的串型号、适用条件和子件信息也需要从 PDF 提取并由红光人员把关。若来源、版本、权限和包边界管理不严，容易出现错误匹配、旧数据沿用、重复计价、成本泄露和报价无法回查。

## Solution

建设一期内网 B/S 报价工作台，按“项目 → 询价包”组织业务。销售建立项目和包并上传资料；系统接收解析结果和来源；U9 手工汇总表作为辅助映射候选，国网图册 PDF 拆解为结构化数据并与人工录入数据比对；红光人员审核后按整批版本发布检索基础。技术根据检索候选、图册来源和适用条件确认金具串、单件及子件；销售和技术完成当前版本确认；系统生成混合 BOM；财务按 U9 子件价格和分配量复算成本，生成三档方案并可调整毛利率；审批实例绑定当前版本；指定财务人员签发不可变报价快照；销售下载对外文件并记录外发、议价和成交结果。

## User Stories

1. 作为销售，我希望建立项目并录入地区、电网类型和电压等级，以便统一管理报价条件。
2. 作为销售，我希望在一个项目下建立多个询价包，以便广覆盖争取中标。
3. 作为销售，我希望每个询价包独立形成报价，以便包之间互不覆盖。
4. 作为销售，我希望上传清单、规范、图册和附件，以便保留完整原始资料。
5. 作为销售，我希望看到每个文件的处理状态、来源和失败原因，以便可以单独重试。
6. 作为技术，我希望查看字段源值、标准化值、建议值和人工确认值，以便追溯识别过程。
7. 作为红光人员，我希望导入客户手工 U9 汇总表并保留版本和来源，以便将其作为辅助映射候选。
8. 作为红光人员，我希望审核重复、冲突和过期的 U9 记录，以便只有可靠映射进入检索版本。
9. 作为红光人员，我希望从国网图册 PDF 抽取串型号、适用条件、子件、数量和材质，以便建立检索基础。
10. 作为红光人员，我希望图册结构化结果与人工录入数据自动比对，以便缺失和不一致内容进入技术确认。
11. 作为技术，我希望回查图册版本、分册、图号或页码和来源位置，以便确认候选依据。
12. 作为技术，我希望按规范编码、串型号、图册和品名描述检索候选，以便组合使用可用路径。
13. 作为技术，我希望确认金具串、单件、子件和适用条件，以便未确认内容不能直接计价。
14. 作为销售，我希望指派风险任务并记录转交，以便问题责任清楚。
15. 作为风险负责人，我希望记录等待补充、处理结果和依据，以便授权人员完成结案。
16. 作为销售，我希望确认客户需求和报价范围，以便保留排除项和恢复依据。
17. 作为技术，我希望确认当前技术选型和版本，以便销售确认不能替代技术确认。
18. 作为销售与技术，我希望在同一 BOM 中看到金具串和单件，并通过对象类型和技术 ID 区分，以便混合货物清单可核对。
19. 作为销售与技术，我希望分别看到采购套数、每套用量和总用量，以便数量关系可复核。
20. 作为财务，我希望统一按 U9 子件价格 × 子件分配量计算，以便金具串和单件金额口径一致。
21. 作为财务，我希望系统生成保守、标准、竞争三档方案，以便快速获得推荐报价。
22. 作为财务，我希望调整毛利率并重新计算，以便根据商务策略修订报价。
23. 作为财务，我希望每次调价形成新方案版本并记录原因，以便审计和重审。
24. 作为审批人员，我希望只能处理绑定给自己的当前节点，以便审批过程不可代办和跳步。
25. 作为指定财务签发人，我希望冻结需求、技术、价格和审批依据，以便签发结果不可被原地改写。
26. 作为销售，我希望下载只含对外字段的报价文件，以便内部成本和毛利不泄露。
27. 作为销售，我希望记录外发、议价和成交结果，以便下载不被误认为客户已收到。
28. 作为业务人员，我希望未中标包保持只读并可继续重报价，以便历史与后续机会同时保留。
29. 作为管理员，我希望维护账号、角色和项目授权，以便每个业务请求都经过服务端权限校验。
30. 作为验收人员，我希望区分原型回归、契约模拟、真实联调和生产验收，以便证据边界清楚。

## Implementation Decisions

- 领域词汇以 `CONTEXT.md` 为准；项目与询价包、检索来源、混合 BOM 和版本化审批的取舍记录在 `docs/adr/`。
- 项目包含多个询价包。询价包独立完成资料处理、销售确认、技术确认、BOM、核价、审批、签发和外发跟进。
- 一期只覆盖国网项目的金具串与单件；二者可在同一货物清单和同一 BOM 中并存。
- U9 汇总表是辅助映射候选，不是未经审核的正式主数据。图册 PDF 拆解为结构化数据，并与人工录入数据比对；差异并列保留，由红光技术人员确认后发布。
- 图册记录必须保留图册版本、分册、图号或页码、串型号、适用条件、子件组成、数量和来源位置。
- 检索基础按整批版本发布。新版本只影响新检索；历史报价继续引用原检索版本。
- BOM 使用业务字段加稳定技术 ID。金具串展开子件，单件保留自身物料与数量；采购套数、每套用量和总用量分别保存，空值不自动转换为零。
- 金具串和单件一期统一按 U9 子件价格乘子件分配量核价。单件工艺路线可保存，但现阶段不计入报价。
- 系统生成保守、标准、竞争三档方案。财务可以调整毛利率；每次调整生成新方案版本，记录前后值、人员、时间、原因和结果，未保存计算不能进入审批。
- 销售确认和技术确认均为当前版本且技术阻断解除后，才能进入核价。
- 审批实例提交时复制启用流程版本、节点、顺序、指定人员、核价版本和政策版本。流程切换不影响进行中的实例。
- 签发生成不可变报价快照。外发、议价和成交分别记录；未中标包保留只读历史，后续报价创建新版本。
- 销售不可见成本与毛利；技术不可见成本与最终商务金额；财务查看成本、毛利和报价；董事长查看审批所需价格；红光人员维护检索基础，不因该职责自动获得业务审批权。
- 外部解析服务、U9、ERP 和 MES 只读接入。本系统保存映射、审核版本、引用快照和审计记录。

## Testing Decisions

- 从公开业务接口或页面到服务端的完整路径验证业务行为，包含成功、拒绝、重复请求、旧版本提交和跨项目越权。
- U9 汇总表、图册结构化数据和人工录入数据的比对测试必须检查重复、冲突、缺失、来源位置和审核发布版本。
- BOM 测试必须检查混合串/单件、技术 ID、采购套数、每套用量、总用量、空值与零值，以及统一核价口径。
- 报价测试使用固定成本和毛利率样例核对三档方案、人工调价新版本、含税/不含税结果和审计字段。
- 导出测试实际读回文件，验证对外字段白名单、技术 ID、来源版本、数量和金额。
- 原型回归、契约模拟、真实接口联调和生产验收独立记录；模拟数据不能替代真实 U9、图册样本、账号、内网和并发验收。
- 生产验收使用独立账号、固定样本、批准阈值和可回查文件，记录未完成原因，不把文档覆盖率当成功能通过率。

## Out of Scope

- 一期不把单件工艺路线和工艺价格计入报价。
- 一期不写回 U9、ERP 或 MES。
- 不自动向客户发送报价，不以下载事件推定客户收到。
- 不包含二期单品成本库、材料价导入、品类扩充和报价比对。
- 不包含三期报告关联、参数化出图和工程图生成。
